# PAPPA: журнал изменений.
#
# Правило: одна запись = один осмысленный шаг (метод, контракт, порт, ворота).
# Для портов полезно указывать числа приёмки (векторы, тесты, max|Δr|).

## 0.1.0 — 2026-09-25

Первый размеченный рубеж: метод заморожен, контракт описан и проверяем, все
заявленные языки сходятся с референсом численно.

**Метод** (зафиксирован, подробности — `docs/method.md`)

* адаптивная степень по правилу RMSE-«локтя» (допуск 5 %) вместо исторической
  метрики по нормализованной амплитуде;
* фичер ям: оконный гаусс 3.2σ (ядро 2σ) с отсечкой невидимых членов
  (`pit_min_amp = 3e-3 мм`), одна общая фаза раскладки (N = 7, 24.75°);
* единый канон координат: `x = Δ/half_train ∈ [-1, 1]` для обучения, оценки и
  сохранённых коэффициентов;
* детектор ям `band` (узкая/широкая медиана + порог в MAD-ах) и авто-очистка
  `iqr` с предохранителем на долю отбрасываемых точек.

**Контракт**

* `spec/pappa.schema.json` — JSON Schema документа сечения (`pappa v2.0`);
* `spec/sample.schema.json` — JSON Schema манифеста папки образца
  (`pappa-sample v1.0`);
* `spec/check_schema.py` — проверка документов по схемам без зависимостей
  (+ инварианты `len(patches) == n_patches`, `len(coefs) == degree + 1`,
  чётность степени, согласованность манифеста и документов);
* `spec/conformance/` — 4 golden-вектора (модель без ям, модель с ямами,
  детектор, очистка) и документированные допуски.

**Реализации**

* референс на Python (`python/pappa/`) и 11 портов: C++17, C99, Go, JavaScript,
  Java, Kotlin, Rust, Free Pascal, Swift, Julia, R — каждый полный пайплайн
  «CSV → папка образца» + свои ворота;
* R-порт: только base R (без пакетов) — свой JSON, CSV, статистика и МНК через
  QR Хаусхолдера;
* приёмка всех портов: конформанс-векторы пройдены, папка образца совпадает с
  референсом численно — 10/10 сечений, `max|Δr| = 1.34e-12 … 1.38e-12 мм` при
  допуске `1e-6` мм.

**Инструменты и документация**

* `verify_all.ps1` — одна команда: ворота всех реализаций (векторы, тесты,
  `-Full` добавляет пайплайн и числовую сверку; `SKIP` для отсутствующих
  тулчейнов);
* `docs/method.md` — формальное описание метода, пайплайна, сериализации,
  допусков и ловушек переноса;
* `docs/embedded.md` — выполнимость C-ядра на микроконтроллерах;
* `CONTEXT.md` — внутренний журнал разработки (решения и их причины), не
  читательский документ.
