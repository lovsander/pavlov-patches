# Conformance

«Золотые» наборы **вход → ожидаемый выход**, по которым проверяется любой порт
PAPPA (C++, Go, C, …) — без Python и без папок образцов. Это контракт метода,
зафиксированный числами.

## Как это работает

1. **Референс (Python) генерирует векторы один раз** и они коммитятся:
   ```bash
   python python/studies/make_conformance.py          # -> spec/conformance/vectors/*.json
   ```
2. **Порт читает те же файлы** и проверяет себя:
   ```bash
   cpp/build-cmake/msvc-release/Release/pappa_conformance spec/conformance/vectors
   # или через ctest: ctest --preset msvc-release -R conformance_vectors
   ```
   Коды: `0` — всё сошлось, `1` — есть расхождения, `2` — нет каталога.

Порт считается корректным, когда проходит все векторы в пределах допусков.
Вход в векторах — аналитический профиль (маленький, читаемый, воспроизводимый
где угодно), поэтому файлы можно держать в репозитории и диффить.

## Формат вектора (JSON)

```jsonc
{
  "format": "pappa-conformance", "version": "1.0",
  "kind": "model" | "detector" | "cleaner",
  "name": "...",
  "tolerance": {"coefs_rel": 1e-9, "coefs_abs_floor": 1e-8, "curve_mm": 1e-6, "frac": 0.02},
  "config": { ... параметры ступени ... },
  "input":  {"angles_deg": [...], "radii_mm": [...]},
  "expected": { ... что должно получиться ... }
}
```

По видам (это ступени пайплайна — падение сразу говорит, ГДЕ расхождение):

| kind | config | expected |
|------|--------|----------|
| `model` | `n_patches`, `phase_deg`, `deg_min/max`, `overlap_train/use`, `deg_elbow_tol`, `coord_mode`, `pits_deg` (+ параметры окна ям) | `degrees`, `coefs` по патчам, `pit_terms` по патчам, `curve` (углы + радиусы) |
| `detector` | окна и порог детектора (`window_deg`, `wide_deg`, `smooth_deg`, `k`, `min_zone_deg`) | `zones_deg`, `pits_deg` |
| `cleaner` | `baseline_deg`, `iqr_k` | `n_outliers`, `mask_true_indices` |

## Допуски — почему такие

* **контур** (`curve_mm` = 1e-6 мм) — главный критерий: он и есть метод;
* **коэффициенты** — `|Δc| ≤ max(coefs_abs_floor, coefs_rel·|c_ожид|)`.
  Абсолютный порог 1e-9 здесь неверен: разные корректные МНК-решатели
  (numpy `lstsq`/SVD и QR Хаусхолдера) на расширенном ямном базисе расходятся
  на ~1e-9 — это разница алгоритмов, а не ошибка порта;
* **детектор/очистка** (`frac`) — зона на самом пороге может «дрогнуть» на точку
  сетки, поэтому сравнивается доля от числа точек, а центры ям — с 1e-6°.

## Когда перегенерировать

Векторы меняются вместе с методом (новая политика степени, другое окно фичера и
т. п.). Порядок: поменять код референса → `make_conformance.py` → прогнать
`pappa_conformance` / `ctest` → закоммитить и код, и векторы в одном шаге, указав
в сообщении, что именно изменилось в ожиданиях.

## Важно: вектор должен быть НЕТРИВИАЛЬНЫМ

Проверка ловит ошибки только там, где ожидание непустое. Дважды наступали на это:

* **детектор.** Гладкая гауссова яма не создаёт разницы узкой (1°) и широкой (10°)
  медиан, а на идеально гладком профиле робастная sigma самого индикатора ~ 0 →
  нормализация даёт нули. Вектор `detector` раньше **ничего не проверял** (0 зон у
  всех портов). Починено: ямы сделаны узкими «ступенями» (1.5° и 1.0°), в профиль
  добавлена шумовая подложка 47° и 13° (высокая частота даёт band, низкая — масштаб
  остатка). Теперь вектор содержит **2 зоны и 2 ямы**, и C++/Go/C проходят его
  по-настоящему;
* **очистка — ОТКРЫТЫЙ ВОПРОС.** Вектор `cleaner` по-прежнему содержит
  `n_outliers = 0` и пустую маску, хотя во вход добавлены всплески +0.9 мм на
  шумовой подложке. Диагностика: у остатка `res = r − медиана(окно 3 точки)` IQR
  выходит ~0 (медиана снимает и рябь, и высокочастотный шум), а при нулевом
  масштабе порог Тьюки `|res − med| > iqr_k · IQR` не срабатывает (в реализации
  есть защита `denom = spread if spread > 1e-12 else 1.0`, то есть порог становится
  3 мм). Нужно разобраться в `AutoOutlierCleaner.clean()` (python/pappa/core/
  outlier_cleaner.py) и подобрать вход, на котором референс **что-то** помечает —
  иначе эта ступень у всех портов проверяется «ни на чём».
