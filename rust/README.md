# Rust порт PAPPA

Piecewise Adaptive Poly-Patch Approximation (PAPPA) на Rust — **полный порт**:
ядро метода (патчи с адаптивной степенью и нормированной координатой,
smoothstep-смешивание = partition of unity, фичер оконных гауссовых ям), детектор
трещин (band), авто-очистка выбросов (iqr) и пайплайн: CSV с сечениями → папка
образца в том же формате, что у референса Python и портов C++/C/Go/JS/Java/Kotlin.

**Зависимостей нет** — ни одного крейта: JSON, CSV, форматирование чисел и «дата
в ISO» написаны своими силами, поэтому `cargo build` работает **офлайн** и не
тянет реестр. Проверено на rustc/cargo **1.98.1** (rustup, stable-x86_64-pc-windows-msvc).

Числа обязаны совпадать с референсом, поэтому повторены тонкости numpy
(медиана как `np.median`, перцентиль с линейной интерполяцией, округление
«половина к чётному» в окне, круговые окна).

## Сборка и запуск

```powershell
# cargo из rustup лежит в %USERPROFILE%\.cargo\bin — если его нет в PATH:
$env:Path = "$env:USERPROFILE\.cargo\bin;$env:Path"

cd rust
cargo build --release --offline          # без сети: зависимостей нет
cargo test  --release --offline          # 3 теста: векторы, дымовой тест, round-trip документа

.\target\release\conformance.exe ..\spec\conformance\vectors
.\target\release\pappa.exe --input ..\python\synthetic_data.csv `
    --out-dir ..\samples\synthetic_sphere_rust --name synthetic_sphere

python python/studies/verify_port.py --py-dir samples/synthetic_sphere `
                                     --cpp-dir samples/synthetic_sphere_rust
```

Ключи пайплайна: `--input`, `--out-dir` (обязательны), `--name`, `--description`,
`--no-pits`, `--quiet`. По умолчанию — как в референсе: N=7, фаза 24.75°, степени
4…14, авто-iqr, фичер ям включён. CSV читается по заголовку: нужны колонки
`section_id, height_mm, angle_deg, radius_mm`.

## Состав

| Файл | Назначение |
|---|---|
| `src/signal.rs` | медиана/перцентили/MAD/окна по кольцу/фильтры — как numpy |
| `src/linalg.rs` | МНК через QR (Хаусхолдер) + базис Чебышёва (схема Кленшоу) |
| `src/cleaner.rs` | авто-очистка выбросов (iqr): медианный фильтр + усы Тьюки |
| `src/detector.rs` | детектор ям: узкая/широкая медиана → индикатор в MAD-ах → зоны |
| `src/model.rs` | `Model`: локальные степени, smoothstep-смешивание, фичер ям, метрики |
| `src/json.rs` | мини-JSON: разбор (`Value`) и запись, 0 зависимостей |
| `src/csv.rs` | чтение CSV по заголовку + посекционный расчёт |
| `src/document.rs` | документ `NN.pappa.json` и папка образца (`sample.json`) |
| `src/conformance.rs` | проверка конформанс-векторов (допуски как у остальных портов) |
| `src/bin/conformance.rs` | проверка порта по векторам (коды 0/1/2) |
| `src/bin/pappa.rs` | пайплайн: CSV → папка образца |
| `tests/conformance.rs` | `cargo test`: векторы, гладкий контур, round-trip документа |

## Заметки по совместимости

* **Округление окна** — `f64::round_ties_even`, а не `round()`: Python
  `round(2.5) == 2` (половина к чётному), а Rust `round()` округляет половину
  **от нуля**; иначе окна разъехались бы (та же тонкость, что `Math.rint` в
  JVM-портах и `math.RoundToEven` в Go).
* **Числа в документе** — `json::num`: целые без дробной части, иначе shortest
  round-trip; очень большие/малые — в экспоненциальной форме (`1e-12`), это
  валидный JSON и Python его парсит.
* **Дата в ISO** — своими силами (`civil_from_days`, алгоритм Хиннанта): в
  стандартной библиотеке Rust форматирования даты нет, а тянуть `chrono` ради
  одной строки в манифесте не хотелось.
* **`pit_terms`** пишется у КАЖДОГО патча модели с ямами (включая пустой список) —
  этого требует загрузчик Python-референса; тест `document_round_trip_smoke`
  проверяет ровно это (7 ключей при ямах, 0 без ям).
* **Свип степеней без QR**: одно накопление матрицы Грама в базисе Чебышёва на
  патч вместо 6 факторизаций; нормальная матрица степени `d` — ведущая
  подматрица матрицы `degMax`, RMSE считается по явным остаткам (Кленшоу).
* **Сборка офлайн**: `--offline` в примерах выше — чтобы явно было видно, что
  сеть не нужна (крейтов нет вообще).
* Собранный `rust/target` в git не попадает (см. корневой `.gitignore`).
