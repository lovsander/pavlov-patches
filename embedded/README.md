# PAPPA на микроконтроллерах: рабочие проекты

Здесь живут проверяемые прогоны PAPPA на реальном железе (через симулятор Wokwi)
и на хосте. Общая идея и замеры — в `docs/embedded.md`.

## Что уже есть

* `pappa_int.{h,c}` — **переносимое целочисленное ядро**: накопление матрицы
  Грама в базисе Чебышёва (Q24, int64-аккумуляторы), правило «локтя» по явным
  остаткам (Clenshaw) с **абсолютным полом**, переход Чебышёв → мономы целочисленный.
  Собирается и под AVR (avr-gcc), и под x86 (gcc) — одни и те же числа.
  Ёмкости массивов задаются флагами `-DPP_MAX_PATCHES -DPP_MAX_DEG`.
* `board_main.c` — прошивка для обоих AVR (регистры UART/таймера совпадают),
  сечение во ФЛЕШЕ, время обучения меряется таймером на чипе.
* `host_main.c` — та же сборка на хосте (сверка «чип vs хост» бит-в-бит).
* `uno/`, `mega/` — проекты под Uno (ATmega328P) и Mega (ATmega2560):
  `diagram.json` + `wokwi.toml` для симулятора Wokwi.
* `tools/section.py` — сечение для теста (`--board`), пишет `<board>/section_data.h`.
* `tools/check.py` — проверка: референс на Python (double) против чисел устройства.
* `build_uno.ps1 -Board <uno|mega>` — сборка avr-gcc + отчёт о размере.

## Как запускать

```bash
# 1) данные сечения в прошивку (пресеты: uno, mega)
python embedded/tools/section.py --board uno

# 2) сверка на хосте (тот же C-код, double-референс на Python)
python embedded/tools/check.py --board uno --host     # -> код 0, если всё сошлось

# 3) сборка под плату: флеш/RAM/кадры стека
powershell -File embedded/build_uno.ps1 -Board uno

# 4) симуляция в Wokwi (нужен токен, см. ниже)
$env:WOKWI_CLI_TOKEN = 'wok_...'                      # https://wokwi.com/dashboard/ci
python embedded/tools/check.py --board uno --wokwi
```

`check.py --wokwi` смотрит не только на код возврата: он забирает serial-лог
(`<board>/build/serial.log`), сверяет степени, таблицу RMSE и кривую (`max|dr|`)
с Python-эталоном на **том же** квантованном сечении. Кривая сверяется по
коэффициентам Чебышёва с устройства (устойчивая форма, см. урок 2 ниже).

| проект | плата | конфигурация |
|--------|-------|--------------|
| `embedded/uno/` | Arduino Uno (ATmega328P) | 360 точек, 3 патча, окно 91, deg ≤ 8 |
| `embedded/mega/` | Arduino Mega (ATmega2560) | 720 точек, 7 патчей, окно 183, deg ≤ 10 |

## Требования к тулчейну (Windows)

```powershell
# Wokwi CLI
iwr https://wokwi.com/ci/install.ps1 -useb | iex          # -> %USERPROFILE%\.wokwi\bin

# AVR-тулчейн (avr-gcc + avr-libc + binutils) через MSYS2
C:\msys64\usr\bin\pacman.exe -S --needed mingw-w64-x86_64-avr-gcc mingw-w64-x86_64-avr-libc
```

`downloads.arduino.cc` (официальный `arduino:avr` для arduino-cli) в этой сети
отдаёт **403**, поэтому прошивка собирается голым avr-gcc без ядра Arduino —
для теста ядра это даже чище: видно чистые флеш/RAM/циклы.

## Измерено (этап 2: два Arduino, симулятор Wokwi)

Прошивка прогнана в Wokwi на **двух** симулированных платах: `PAPPA_DONE` →
`TEST PASSED`, числа с чипа совпадают с хост-сборкой того же C-кода (бит-в-бит)
и с Python-эталоном.

| плата (ядро) | конфигурация | флеш | статич. RAM | **TIME_US** | max\|dr\| vs Python |
|---|---|---|---|---|---|
| Uno (ATmega328P, 2 КБ/32 КБ) | 3 патча, 360 точек, окно 91, deg ≤ 8 | 14 492 Б (44.2 %) | 406 Б (19.8 %) | **767 156 мкс** | 9.7e-8 мм |
| Mega (ATmega2560, 8 КБ/256 КБ) | 7 патчей, 720 точек, окно 183, deg ≤ 10 | 16 194 Б (6.2 %) | 486 Б (5.9 %) | **4 427 520 мкс** | 3.9e-7 мм |

Разложение по фазам (`pp_tick()` = таймер на чипе):

| фаза | Uno, мкс | Mega, мкс |
|------|---------:|----------:|
| накопление Грама и правой части | 388 624 (51 %) | 2 618 952 (59 %) |
| «локоть»: решения + явные остатки (float) | 337 884 (44 %) | 1 700 940 (38 %) |
| финальное решение + переход Чебышёв→мономы | 40 044 (5 %) | 105 764 (2 %) |

Степени, выбранные «локтем» на Mega (7 патчей): 8, 10, 8, 8, 8, 8, 8 — совпали
с референсом на всех патчах, включая тот, что накрывает трещину.

## Уроки, полученные на этом коде (важно для портов)

1. **Ширина операндов решает на AVR.** Пока базис Чебышёва и `yc` лежали в
   `int64_t`, каждое произведение шло через `__muldi3` (64×64→64, сотни циклов):
   обучение занимало **986 мс**. Достаточно держать значения в `int32_t`
   (Q24 влезает: |T| ≤ 2^24) и приводить к int64 только в произведении — это
   32×32→64 (одна пара `mul`), и время упало до **700 мс** (и флеш на 1 КБ меньше).
   Числа при этом не изменились ни на бит.
2. **Устройство должно отдавать коэффициенты ЧЕБЫШЁВА, а не мономиальные.**
   На Uno это не проявлялось (степени ≤ 8, окна гладкие), а на Mega патч с
   трещиной при степени 10 дал мономиальные коэффициенты, где float32 теряет
   точность из-за плохой обусловленности формы: расхождение кривой **4.3e-2 мм**.
   Переход на вывод коэффициентов Чебышёва (они ограничены амплитудой данных,
   вычисление по Clanshaw) дал **3.9e-7 мм**, а в мономы для документа их
   переводит хост в double (переход точный: у T_k целые коэффициенты).
3. **Сдвиг при накоплении нельзя делать «на каждом слагаемом»** — усечение по
   1 LSB на точку давало ошибку кривой 3e-5 мм. Произведения (T_i·T_j ≤ 2^48,
   T_i·y ≤ ~5e12) при окне ≤ 4096 точек влезают в int64 — копим БЕЗ сдвига,
   масштабируем один раз при решении (2^-48 и 2^-24).
4. **Модель отдаётся относительно опорного радиуса** (`YREF`): если прибавить
   на устройстве 15 мм, ULP float32 (~1e-6 мм при 15 мм) съедает весь допуск
   метода. Абсолютный радиус прибавляет хост, в double.
5. **RMSE только по явным остаткам** и **абсолютный пол** в правиле «локтя» —
   иначе степень выбирает разрядность решателя, а не данные.
6. **Soft-float дорог.** 38–44 % времени — решения и подсчёт остатков во `float`
   (на AVR каждое действие — вызов libm, ~150 циклов). Следующий шаг —
   считать остатки в целых (ожидаемо ~10× на этой фазе).

## Что это значит по железу

* **Uno**: сечение 360 точек × 3 патча = **0.77 с**. Годится для медленного
  сканирования; с фиксированной степенью (фаза «локтя» исчезает) и целыми
  остатками реально уйти в ~0.15–0.25 с.
* **Mega**: 720 точек × 7 патчей = **4.4 с** — время растёт как (патчи)·(окно)²,
  зато запас по флешу (6 %) и RAM (6 %) огромный: можно и 2000 точек, и степени
  до 14.
* Старшие платы (M4F/M7/ESP32) на этом коде дают те же числа в ~50–200 раз
  меньше, то есть десятки миллисекунд на сечение даже без оптимизаций.

## Как посмотреть результат симуляции

`python embedded/tools/check.py --wokwi` печатает фазовые времена (`PHASE …`),
`TIME_US` и таблицу сверки; serial-лог сохраняется в `uno/build/serial.log`.
Токен (`WOKWI_CLI_TOKEN`, вид `wok_…`) берётся на https://wokwi.com/dashboard/ci,
free-тариф даёт 50 минут симуляции в месяц (наш прогон — единицы секунд).
