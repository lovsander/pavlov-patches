# PAPPA на микроконтроллерах: рабочие проекты

Здесь живут проверяемые прогоны PAPPA на реальном железе (через симулятор Wokwi)
и на хосте. Общая идея и замеры — в `docs/embedded.md`.

## Что уже есть

* `pappa_int.{h,c}` — **переносимое целочисленное ядро**: накопление матрицы
  Грама в базисе Чебышёва (Q24, int64-аккумуляторы), правило «локтя» по явным
  остаткам (Clenshaw) с **абсолютным полом**, переход Чебышёв → мономы целочисленный.
  Собирается и под AVR (avr-gcc), и под x86 (gcc) — одни и те же числа.
* `host_main.c` — та же сборка на хосте (сверка «чип vs хост» бит-в-бит).
* `uno/` — прошивка для **Arduino Uno (ATmega328P)**: bare-metal, сечение во флеше,
  UART 9600, время обучения измеряется таймером на чипе (`TIME_US`).
* `tools/section.py` — сечение для теста (генерирует `uno/section_data.h`).
* `tools/check.py` — проверка: референс на Python (double) против чисел устройства.
* `build_uno.ps1` — сборка avr-gcc + отчёт о размере (флеш/RAM/кадры стека).

## Как запускать

```bash
# 1) данные сечения в прошивку
python embedded/tools/section.py

# 2) сверка на хосте (тот же C-код, double-референс на Python)
python embedded/tools/check.py --host          # -> код 0, если всё сошлось

# 3) сборка под Uno: флеш/RAM/кадры стека
powershell -File embedded/build_uno.ps1

# 4) симуляция на Uno в Wokwi (нужен токен, см. ниже)
$env:WOKWI_CLI_TOKEN = 'wok_...'               # https://wokwi.com/dashboard/ci
python embedded/tools/check.py --wokwi
```

`check.py --wokwi` смотрит не только на код возврата: он забирает serial-лог
(`uno/build/serial.log`), сверяет степени, таблицу RMSE и кривую (`max|dr|`)
с Python-эталоном на **том же** квантованном сечении.

## Требования к тулчейну (Windows)

```powershell
# Wokwi CLI
iwr https://wokwi.com/ci/install.ps1 -useb | iex          # -> %USERPROFILE%\.wokwi\bin

# AVR-тулчейн (avr-gcc + avr-libc + binutils) через MSYS2
C:\msys64\usr\bin\pacman.exe -S --needed mingw-w64-x86_64-avr-gcc mingw-w64-x86_64-avr-libc
```

`downloads.arduino.cc` (официальный `arduino:avr` для arduino-cli) в этой сети
отдаёт **403**, поэтому прошивка собирается голым avr-gcc без ядра Arduino —
для теста ядра это даже чище: видно чистые флеш/RAM/циклы.

## Измерено (этап 1)

| что | значение |
|-----|----------|
| флеш ATmega328P | 14 168 Б (43.2 % из 32 КБ) |
| статическая RAM | 364 Б (17.8 % из 2 КБ) |
| кадр стека `pp_fit` | 1 060 Б (плюс 242 Б в `main`) |
| сверка хоста с Python-эталоном | степени 8/8/8, `max|dr|` = 1.4e-7 мм при допуске 1e-6 |

Итого на Uno занято ≈1.8 КБ из 2 КБ — влезает, но впритык (см. выводы в
`docs/embedded.md`: на «младших» лучше 1–2 патча или окно поменьше).

## Уроки, полученные на этом коде (важно для портов)

1. **Сдвиг при накоплении нельзя делать «на каждом слагаемом»** — усечение по
   1 LSB на точку давало ошибку кривой 3e-5 мм. Произведения (T_i·T_j ≤ 2^48,
   T_i·y ≤ ~5e12) при окне ≤ 4096 точек влезают в int64 — копим БЕЗ сдвига,
   масштабируем один раз при решении (2^-48 и 2^-24).
2. **Модель отдаётся относительно опорного радиуса** (`YREF`): если прибавить
   на устройстве 15 мм, ULP float32 (~1e-6 мм при 15 мм) съедает весь допуск
   метода. Абсолютный радиус прибавляет хост, в double.
3. **RMSE только по явным остаткам** и **абсолютный пол** в правиле «локтя» —
   иначе степень выбирает разрядность решателя, а не данные.
