# VBA порт PAPPA (Microsoft Excel, VBA 7)

Piecewise Adaptive Poly-Patch Approximation (PAPPA) на **VBA 7** (Microsoft Excel) —
**полный порт**: ядро метода (патчи с адаптивной степенью и нормированной
координатой, smoothstep-смешивание = partition of unity, фичер оконных гауссовых
ям), детектор трещин (band), авто-очистка выбросов (iqr) и пайплайн: CSV с
сечениями → папка образца в том же формате, что у референса Python и остальных
портов.

**Зависимостей нет, кроме самого Excel**: свой разбор и запись JSON, CSV,
медианы/перцентили/MAD, МНК (QR Хаусхолдера) и метка времени. Библиотек и
COM-объектов (`Scripting.Dictionary`, `FileSystemObject`, `ADODB`) в порте нет
намеренно — только язык и один вызов Win32 (`GetSystemTime`, см. ниже). Проверено
на **Excel 16.0** (Office 2016; x86 и x64 — объявления `PtrSafe`).

Зачем этот порт: Excel — то место, где измерения реально смотрят и правят до
экспорта, а VBA-порт не требует ни компилятора, ни тулчейна, кроме уже
установленного Office. Плата за это — скорость (Excel-VBA в разы медленнее
скомпилированных портов) и несколько серьёзных ловушек платформы, которые
перечислены ниже: они дороже по времени, чем сама арифметика метода.

## Сборка и запуск

Компиляции как таковой нет: `.bas`-модули импортируются в книгу Excel и
вызываются через COM (`Application.Run`). Скрипт сборки ищет установку Office
(стандартные пути `Office16`, затем PROGID `Excel.Application`).

```powershell
powershell -File vba/build_vba.ps1             # модули грузятся (Smoke)
powershell -File vba/build_vba.ps1 -Vectors    # конформанс-векторы spec/conformance/vectors
powershell -File vba/build_vba.ps1 -Test       # + самопроверка (векторы, юниты, round-trip)
powershell -File vba/build_vba.ps1 -Pipeline   # + samples/synthetic_sphere_vba

python python/studies/verify_port.py --py-dir samples/synthetic_sphere `
                                     --cpp-dir samples/synthetic_sphere_vba
python spec/check_schema.py samples/synthetic_sphere_vba
```

| Ключ | Что делает |
|---|---|
| `-Vectors` | точка входа `PappaConformance.pappa_conformance_run(<каталог векторов>)` |
| `-Test` | точка входа `PappaSelftest.pappa_selftest_run(<каталог векторов>)` — векторы + юниты + дымовой фит + round-trip папки образца |
| `-Pipeline` | точка входа `PappaPipeline.pappa_pipeline_run(<csv>, <out-dir>, <name>)` |
| `-Input` / `-OutDir` / `-Name` | параметры пайплайна; по умолчанию `python/synthetic_data.csv`, `samples/synthetic_sphere_vba`, `synthetic_sphere` |
| `-TimeoutSec` | предел на прогон (по умолчанию 900 с): по нему убивается зависший Excel |
| `-Clean` | снести `vba/build` и собрать заново |
| `-NoSetViolationModel` | не выставлять `AccessVBOM` (тогда при отсутствии флага — понятная ошибка вместо правки реестра) |

Что скрипт делает до старта Excel:

* конвертирует исходники из UTF-8 в **cp1251** (редактор VBA читает импортируемый
  `.bas` как ANSI — иначе кириллица в комментариях станет мусором);
* проверяет **уникальность Public-имён** между модулями: VBA держит стандартные
  модули в ОДНОМ глобальном пространстве имён, а дубль имени даёт не ошибку
  компиляции с текстом, а `RPC_E_SERVERFAULT` от Excel. Сейчас в порте
  116 public-процедур;
* проверяет, что нигде нет `ByVal x() As T`: массивы в VBA передаются только по
  ссылке, а `ByVal` перед массивом не компилируется («Ожидается массив»);
* при необходимости одноразово выставляет
  `HKCU\Software\Microsoft\Office\<версия>\Excel\Security\AccessVBOM = 1`
  (доверенный доступ к объектной модели проекта VBA — без него импорт модулей
  через `VBProject` запрещён) и сообщает об этом.

Прогон идёт в **отдельном процессе** (`Start-Job`) с таймаутом; `Interactive =
False` превращает ошибку VBA в исключение COM, а не в модальное окно, иначе
автоматизация зависла бы. Точки входа поэтому не бросают `Err`, а возвращают
отчёт строкой с последней строкой `RESULT: OK` / `RESULT: FAIL n` — по ней
скрипт выставляет код возврата (упавшая проверка не должна «съедать» отчёт).
Подробности прогона пишутся в `vba/build/run.log`, ход — в `vba/build/trace.log`
(путь в переменной окружения `PAPPA_VBA_TRACE`; у VBA нет консоли).


## Модули

| Файл | Назначение |
|---|---|
| `src/PappaKinds.bas` | общие константы: версия порта, ёмкости (`PP_MAX_POINTS` и т.п.) |
| `src/PappaSignal.bas` | медиана/перцентили/MAD/окна по кольцу/фильтры — как numpy |
| `src/PappaLinalg.bas` | МНК через QR (Хаусхолдер) + базис Чебышёва (схема Кленшоу) |
| `src/PappaCleaner.bas` | авто-очистка выбросов (iqr): медианный фильтр + усы Тьюки |
| `src/PappaDetector.bas` | детектор ям: узкая/широкая медиана → индикатор в MAD-ах → зоны |
| `src/PappaModel.bas` | модель: локальные степени, smoothstep-смешивание, фичер ям, метрики |
| `src/PappaJson.bas` | мини-JSON: разбор и запись; дерево — плоская арена на массивах |
| `src/PappaIo.bas` | текстовый ввод-вывод, каталоги, метка времени UTC |
| `src/PappaCsv.bas` | чтение CSV по заголовку (`section_id, height_mm, angle_deg, radius_mm`) |
| `src/PappaDocument.bas` | документ `sections/NN.pappa.json` и манифест `sample.json` |
| `src/PappaConformance.bas` | проверка `spec/conformance/vectors` (допуски как у остальных портов) |
| `src/PappaPipeline.bas` | пайплайн CSV → папка образца |
| `src/PappaSelftest.bas` | самопроверка: векторы + юниты + дымовой фит + round-trip |
| `src/PappaMain.bas` | `Smoke` — «порт грузится» без арифметики |
| `build_vba.ps1` | импорт модулей, режимы `-Vectors` / `-Test` / `-Pipeline` / `-Clean` |

Соглашения модулей (как в Fortran-порте): массивы **всегда 1-базные**
(`ReDim a(1 To n)`), длина берётся из `UBound(a)`, индексация `a(i)`, `i = 1..n`.
Структур-значений с динамическими массивами внутри в VBA нет (UDT не может
содержать перераспределяемый массив), поэтому модель живёт в модульных
переменных, а маски/зоны возвращаются через `ByRef`-аргументы — как в C-порте.

## Заметки по совместимости (ловушки VBA)

Собраны спайками на этой машине (Excel 16.0, ru-RU). Это не «стилистика»: каждая
из них либо меняла числа, либо молча делала не то, что написано.

* **Рабочий каталог Excel — не каталог запуска.** `CurDir$` внутри VBA равен
  `C:\Users\<user>\Documents` независимо от того, откуда запущен скрипт (Excel
  сам назначает себе «Мои документы»). Поэтому относительный путь в порте уехал
  бы в `Documents\samples\...`; скрипт сборки передаёт **абсолютные** пути.
* **Существование пути — только через `GetAttr`, не через `Dir`.**
  `Dir(path, vbDirectory)` **не** возвращает скрытые каталоги: `C:\Users\<user>\
  AppData` скрытый, поэтому проверка «каталог есть?» врала, `io_make_dir` вызывал
  `MkDir` по существующему каталогу и падал с ошибкой 75 «Path/File access
  error». Дополнительно: у `Dir` с атрибутами путь с хвостовым `\` даёт ошибку 52
  «Bad file name or number» (у `GetAttr` — нет), а `Dir(path, vbDirectory)`
  считает совпадением и обычный файл. `GetAttr` возвращает атрибуты (бит
  `vbDirectory` — каталог), а отсутствие пути даёт ошибку 53 (нет файла) или
  76 (нет диска).
* **`dir` как имя переменной затеняет встроенную `Dir`.** Параметр с таким
  именем превращает `dir$(...)` в скаляр с суффиксом типа, и компилятор выдаёт
  «Expected array» — ошибка, не связанная с настоящей причиной. В порте параметр
  называется `folder`.
* **`Open ... For Output` пишет файлы в ANSI (cp1251)**, а документы остальных
  портов — в UTF-8. Порт поэтому пишет ТОЛЬКО ASCII: все не-ASCII символы строк
  уходят в JSON как `\uXXXX`, а такой файл валиден и как UTF-8. Строки в
  документах (описания, `method`, заметки) читаются Python-ом и схемами без
  правок.
* **`Format$`/`Str` печатают не более 15 значащих цифр** (проверено: `1/3` даёт
  `.333333333333333`). Побайтовое совпадение документов с референсом поэтому
  недостижимо: числа пишутся с 15 цифрами, а тесты сверяют round-trip с допуском
  `1e-14` отн. На приёмку это не влияет — контур допускается до `1e-6` мм,
  коэффициенты до `1e-9`.
* **Локаль машины.** В русской локали `Format$` ставит запятую, а `CDbl("1.5")`
  даёт ошибку 13 «Type mismatch». Числа разбираются через `Val` (он не зависит от
  локали), а в строках заменяется запятая на точку. Разделителем CSV остаётся
  запятая-как-разделитель — порт читает файл, а не печатает его.
* **NaN и Infinity в VBA не существуют.** `0/0` — это ошибка времени выполнения
  11, переполнение — ошибка 6, а не значения. Ветки «сумма весов ноль» и
  «ноль в знаменателе» явно ветвятся (в порте случай нулевой суммы весов
  повторяет поведение C-порта — ноль, а не NaN референса).
* **`Mod` усекает к нулю** (`Mod(-1, 360) = -1`), а кольцевым формулам нужна
  floor-семантика Python: в порте своя `sig_mod`. Это ровно та ловушка, что у
  C/C#/JS-портов.
* **`Round` в VBA — «половина к чётному»** (banker's), то есть совпадает с
  `round` в Python/numpy, и эмулировать ничего не нужно — в отличие от
  C/Pascal/Fortran/Octave, где половина уходит от нуля.
* **Одно глобальное пространство имён у модулей.** Два `Public`-имени с
  одинаковым именем ломают проект, и Excel отдаёт только `RPC_E_SERVERFAULT` без
  текста, поэтому дубли ловит скрипт сборки — до старта Excel.
* **Массивы передаются только по ссылке**: `ByVal x() As Double` не
  компилируется. Скрипт сборки проверяет это регуляркой заранее, чтобы не
  получать «Ожидается массив» из COM без номера строки.
* **`Application.Run` — единственный интерфейс.** Публичные функции не могут
  вернуть структуру, поэтому всё общение наружу — строкой отчёта
  (`RESULT: OK` / `RESULT: FAIL n`), а маски и зоны возвращаются через
  `ByRef`-аргументы.
* **CSV на 60 000 строк** читается не в строку, а в массив строк
  (`io_read_lines`): конкатенация строк в цикле квадратична, и пайплайн
  «повисает» без ошибки.
* **UTC.** У VBA есть только `Now` (местное время), поэтому метка пишется из
  `GetSystemTime` (kernel32) — единственный Win32-вызов в порте. Из `Now` вышел
  бы сдвиг часового пояса (та же ловушка, что в Octave-порте).

## Ограничения

* Нужен установленный Microsoft Excel (Office 2016 или новее); на других
  платформах порт не запускается — это свойство платформы, а не метода.
* Скорость: пайплайн 10 сечений × 6000 точек — 11 с против ~1 с у
  скомпилированных портов. Порядок объясняется интерпретацией VBA и запуском
  Excel, а не алгоритмом (числа совпадают машина в машину).
* Точки сверх `PP_MAX_POINTS` и сечения сверх 64 отбрасываются молча — как в
  хостовой сборке C-порта (там это тоже `-DPP_MAX_POINTS`).
* Порт не читает legacy-форматы (`pmodel v1.0`, `appa v2.0`) — только текущий
  контракт `pappa v2.0`.
