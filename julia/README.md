# Julia порт PAPPA

Piecewise Adaptive Poly-Patch Approximation (PAPPA) на Julia — **полный порт**:
ядро метода (патчи с адаптивной степенью и нормированной координатой,
smoothstep-смешивание = partition of unity, фичер оконных гауссовых ям), детектор
трещин (band), авто-очистка выбросов (iqr) и пайплайн: CSV с сечениями → папка
образца в том же формате, что у референса Python и портов
C++/C/Go/JS/Java/Kotlin/Rust/Pascal/Swift.

**Внешних пакетов нет**: JSON, CSV, статистика и ISO-дата написаны своими силами
(в `deps` только стандартная библиотека `Test`), поэтому `julia --project=julia`
работает без `Pkg.instantiate` и без сети. Проверено на **Julia 1.13.0**.

Julia оказалась самым «дружелюбным» языком серии: `round` уже округляет половину к
чётному (как Python), `mod` уже даёт неотрицательный остаток, поэтому кольцевые
формулы пишутся напрямую — без эмуляций из остальных портов.

## Запуск

```powershell
powershell -File julia/build_julia.ps1              # проверка загрузки пакета
powershell -File julia/build_julia.ps1 -Test        # тесты (test/runtests.jl)
powershell -File julia/build_julia.ps1 -Vectors     # конформанс-векторы
powershell -File julia/build_julia.ps1 -Pipeline    # пайплайн на python/synthetic_data.csv

# вручную (скрипт печатает ровно эти команды; julia.exe ищется в ~/.julia/juliaup):
julia --project=julia julia\bin\conformance.jl spec\conformance\vectors
julia --project=julia julia\bin\pappa.jl --input python\synthetic_data.csv `
      --out-dir samples\synthetic_sphere_julia --name synthetic_sphere
python python/studies/verify_port.py --py-dir samples/synthetic_sphere `
                                     --cpp-dir samples/synthetic_sphere_julia
```

Ключи пайплайна: `--input`, `--out-dir` (обязательны), `--name`, `--description`,
`--no-pits`, `--quiet`. По умолчанию — как в референсе: N=7, фаза 24.75°, степени
4…14, авто-iqr, фичер ям включён. CSV читается по заголовку: нужны колонки
`section_id, height_mm, angle_deg, radius_mm`.

`juliaup` ставит лончер в `%LOCALAPPDATA%\Microsoft\WindowsApps`, а сам интерпретатор —
в `%USERPROFILE%\.julia\juliaup\julia-<версия>\bin\julia.exe`; `build_julia.ps1`
находит второй (лончер при каждом вызове проверяет обновления и печатает лишнее).

| `test/runtests.jl` | `Test`: векторы + гладкий контур + round-trip документа |
| `build_julia.ps1` | поиск julia + прогоны (`-Test`/`-Vectors`/`-Pipeline`) |

## Заметки по совместимости (что реально всплыло при портировании)

* **Индексация с 1 — источник off-by-one в CSV.** Проверка «хватит ли колонок» была
  скопирована из 0-based портов (`length(f) <= need`) и на файле из четырёх колонок
  отбрасывала **все** строки: в Julia `need` — это *номер* последней нужной колонки
  (4), то есть условие `4 <= 4` истинно. Пайплайн на 12-колоночном CSV работал,
  поэтому баг нашёл только тест с CSV из четырёх колонок — верное условие `length(f) < need`.
* **`module Model` + `mutable struct Model` ломают док-систему.** Докстринги в
  `src/model.jl` падали с `doc!: no method matching doc!(::Type{Pappa.Model.Model}, …)` —
  коллизия имени модуля и типа. В этом файле докстринги заменены комментариями
  (в остальных файлах докстринги на месте).
* **`using ..Model` затеняет модуль экспортированным типом** — в `src/csv.jl`,
  `src/document.jl` и `src/conformance.jl` стоит `import ..Model`; обращения всё равно
  квалифицированные (`Model.fit!`, `Model.Model`, …).
* **Soft scope**: присваивания внутри циклов на верхнем уровне скрипта Julia трактует
  как локальные переменные, поэтому `bin/*.jl` обёрнуты в `function main()`.
* **`round` и `mod` уже «правильные»**: половина к чётному (как Python `round()` и
  `math.RoundToEven`) и неотрицательный остаток — поэтому кольцевые формулы в
  `src/signal.jl` пишутся напрямую, без эмуляций из остальных портов.
* **Числа в документе** — `json_num`: целые без дробной части, иначе строковое
  представление Julia (shortest round-trip); очень малые — в экспоненте, это валидный JSON.
* **`pit_terms`** пишется у КАЖДОГО патча модели с ямами (включая пустой список) —
  этого требует загрузчик Python-референса; тест это проверяет.
* **Свип степеней без QR**: одно накопление матрицы Грама в базисе Чебышёва на патч
  вместо 6 факторизаций; RMSE — по явным остаткам (Кленшоу).
* **`Pkg.test()` офлайн не работает** (нужен резолв окружения), поэтому `Test` объявлен
  в `deps` и тесты запускаются напрямую: `julia --project=julia julia/test/runtests.jl`.
* **`build_julia.ps1` держит весь исполняемый текст ASCII.** Windows PowerShell 5.1
  читает `.ps1` без BOM в кодировке ANSI; кириллица в UTF-8 при этом «размножается», и
  байт `0x82` превращается в «умную кавычку» U+201A, которую токенайзер считает
  разделителем строки — скрипт падает с `TerminatorExpectedAtEndOfString` ещё на
  разборе файла. Кириллица оставлена только в комментариях (там мусор безвреден),
  сообщения и `throw` — по-английски.
* **Нельзя передавать двойные кавычки в `julia -e` через PowerShell 5.1** — при вызове
  нативной программы они «съедаются» (`println(...)` доезжает обрезанным). Smoke-проверка
  в `build_julia.ps1` обходится без строковых литералов: `println(:Pappa, ' ', Pappa.PORT_VERSION)`.
