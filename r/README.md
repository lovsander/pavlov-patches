# R порт PAPPA

Piecewise Adaptive Poly-Patch Approximation (PAPPA) на R — **полный порт**:
ядро метода (патчи с адаптивной степенью и нормированной координатой,
smoothstep-смешивание = partition of unity, фичер оконных гауссовых ям), детектор
трещин (band), авто-очистка выбросов (iqr) и пайплайн: CSV с сечениями → папка
образца в том же формате, что у референса Python и портов
C++/C/Go/JS/Java/Kotlin/Rust/Pascal/Swift/Julia.

**Внешних пакетов нет** (`jsonlite`, `readr`, `testthat` не используются):
JSON-парсер и писатель, CSV, медианы/перцентили, QR-МНК и ISO-дата написаны
своими силами, поэтому порт работает на голом R. Проверено на **R 4.6.1**
(x86_64-w64-mingw32, ucrt).

Модулей в R нет, поэтому каждый модуль — **окружение**: `Pappa$Signal`,
`Pappa$Linalg`, `Pappa$Cleaner`, `Pappa$Detector`, `Pappa$Model`, `Pappa$Json`,
`Pappa$Csv`, `Pappa$Document`, `Pappa$Conformance`; цепочка родителей
(`Pappa$Model -> Linalg -> Signal -> Pappa -> base`) заменяет `using`/`import`
из Julia-порта, а обращения между модулями такие же квалифицированные
(`Signal$median2`, `Model$fit`). Загрузка — `source("r/src/pappa.R"); Pappa$load("r/src")`.

## Запуск

```powershell
powershell -File r/build_r.ps1              # проверка загрузки порта
powershell -File r/build_r.ps1 -Test        # тесты (r/tests/runtests.R)
powershell -File r/build_r.ps1 -Vectors     # конформанс-векторы
powershell -File r/build_r.ps1 -Pipeline    # пайплайн на python/synthetic_data.csv

# вручную (скрипт печатает ровно эти команды; Rscript.exe ищется в Program Files\R):
Rscript --vanilla r/bin/conformance.R spec/conformance/vectors
Rscript --vanilla r/bin/pappa.R --input python/synthetic_data.csv `
          --out-dir samples/synthetic_sphere_r --name synthetic_sphere
python python/studies/verify_port.py --py-dir samples/synthetic_sphere `
                                     --cpp-dir samples/synthetic_sphere_r
```

Ключи пайплайна: `--input`, `--out-dir` (обязательны), `--name`, `--description`,
`--no-pits`, `--quiet`. По умолчанию — как в референсе: N=7, фаза 24.75°, степени
4…14, авто-iqr, фичер ям включён. CSV читается по заголовку: нужны колонки
`section_id, height_mm, angle_deg, radius_mm`.

`--vanilla` отключает пользовательский профиль `.Rprofile` и сохранение
workspace — на числа порта это не влияет, но делает прогон воспроизводимым.

| `src/model.R` | `Model`: локальные степени, smoothstep-смешивание, фичер ям, метрики |
| `src/json.R` | мини-JSON: списки + парсер + писатель, файловый ввод-вывод |
| `src/csv.R` | чтение CSV по заголовку + посекционный расчёт |
| `src/document.R` | документ `NN.pappa.json` и папка образца (`sample.json`) |
| `src/conformance.R` | проверка конформанс-векторов (допуски как у остальных портов) |
| `bin/conformance.R` | проверка порта по векторам (коды 0/1/2) |
| `bin/pappa.R` | пайплайн: CSV → папка образца |
| `tests/runtests.R` | свой мини-харнесс: векторы, контур, документ, юниты |
| `build_r.ps1` | поиск `Rscript.exe` + прогоны (`-Test`/`-Vectors`/`-Pipeline`) |

## Заметки о совместимости (что реально всплыло при портировании)

* **Модулей нет — есть окружения.** Каждый модуль лежит в `Pappa$<Имя>`
  (`new.env(parent = ...)`), цепочка родителей заменяет `using`/`import`. Для
  `Model` нужны сразу `Signal` и `Linalg`, а родитель у окружения один, поэтому
  модули выстроены в цепочку `Model -> Linalg -> Signal -> Pappa -> base`.
* **`evalq` обязателен.** В R функция захватывает окружение, в котором СОЗДАНА:
  при `Pappa$Signal$f <- function(...)` замыкание уехало бы в `globalenv`, и
  внутренние ссылки на `Signal$...` не разрешились бы. Поэтому тело каждого
  модуля вычисляется через `evalq({...}, Pappa$Signal)`.
* **Родитель `Pappa` — `baseenv()`, а не `emptyenv()`.** Иначе цепочка
  обрывается, и внутри `evalq` не находятся даже базовые `{`, `if`, `sum`
  (ошибка «could not find function "{"»).
* **Внутри `evalq` имя `Pappa` не видно.** Цепочка заканчивается в `baseenv`, а
  сама `Pappa` живёт в `globalenv`, поэтому модули обращаются друг к другу по
  коротким именам (`Model$has_pits`, `Json$json_parse`) — они находятся в
  `Pappa`. Константы версии/языка в `Document` копируются снаружи `evalq`.
* **`[[<-` со значением `NULL` УДАЛЯЕТ элемент списка.** JSON-`null` (например
  `"detector": null` в `sample.json`) терял бы ключ объекта и элемент массива;
  правильно `d[k] <- list(v)` и `a[n] <- list(v)` — это отдельный тест.
* **`round()` и `%%` в R уже «правильные»**: половина к чётному (IEC 60559, как
  `Python round()` и `math.RoundToEven`) и неотрицательный остаток — поэтому
  кольцевые формулы и выбор окна пишутся напрямую, без эмуляций из других портов.
* **Свои медиана и перцентиль, а не `stats::median`/`quantile`/`mad`**: у них
  другие типы интерполяции и масштаб, а референс numpy-совместим. Перцентиль —
  линейная интерполяция по 0-based позиции `(q/100)·(n−1)` (это тип 7 у R и
  дефолт у numpy).
* **МНК — свой `lstsq_qr` (QR Хаусхолдера), а не `base::qr`/`lm.fit`**: LAPACK
  добавляет псевдообработку вырожденных столбцов (pivoting), и коэффициенты
  разошлись бы с остальными портами сильнее допуска вектора (1e-9 отн.).
  Матрица Грама Чебышёва собирается `crossprod` (тот же ряд, но векторизовано).
* **Индексация с 1 — та же ловушка, что в Julia-порте.** Проверка «хватит ли
  колонок» в 0-based портах выглядит как `length(f) <= need`; в R и Julia
  `need` — это НОМЕР последней нужной колонки, поэтому верное условие —
  `length(f) < need`. На 12-колоночном «настоящем» CSV ошибка не видна, её
  ловит тест с четырёхколоночным CSV.
* **`as.character()` в R печатает 15 значащих цифр** (`0.1 + 0.2` → `"0.3"`),
  поэтому `json_num` ищет кратчайшую запись, которая читается обратно в то же
  double (`format(v, digits = d)` с проверкой round-trip), целые пишет без
  дробной части, а `NaN`/`Inf` — как `0`.
* **Числа в документе** для малых величин выходят в экспоненте (`1e-12`) — это
  валидный JSON, и парсер Python (а также собственный парсер порта) читает их.
* **`pit_terms`** пишется у КАЖДОГО патча модели с ямами (включая пустой
  список) — этого требует загрузчик Python-референса; тест это проверяет.
* **Файлы пишутся в режиме `wb` через `writeBin(charToRaw(...))`**, а читаются
  `readLines(encoding = "UTF-8")`: `writeLines` добавил бы лишний перевод строки,
  а `enc2utf8` гарантирует UTF-8 независимо от локали.
* **`build_r.ps1` держит весь исполняемый текст ASCII.** Windows PowerShell 5.1
  читает `.ps1` без BOM в кодировке ANSI, байт `0x82` из кириллицы становится
  «умной кавычкой» U+201A и ломает токенайзер (та же история, что в Julia-порте).
  Smoke-проверка вынесена во временный `.R`-файл, путь к `src/` передаётся
  переменной окружения: двойные кавычки в аргументах нативной программы
  PowerShell 5.1 не сохраняет.
* **Сопровождение:** `Set-Content -Encoding UTF8` в PowerShell 5.1 добавляет
  BOM. Файлы порта — UTF-8 без BOM с переводами строк LF (как в остальном
  репозитории); при правках из PowerShell писать через
  `[IO.File]::WriteAllText($p, $t, (New-Object System.Text.UTF8Encoding($false)))`.
* **Скорость.** R — интерпретатор: 10 сечений × 6000 точек ≈ 27 с (узкое место —
  медианные фильтры по кольцу, они вызывают `sort` на каждую точку). На числа это
  не влияет, поэтому оптимизация не делалась.
