# Octave порт PAPPA

Piecewise Adaptive Poly-Patch Approximation (PAPPA) на GNU Octave — **полный
порт**: ядро метода (патчи с адаптивной степенью и нормированной координатой,
smoothstep-смешивание = partition of unity, фичер оконных гауссовых ям), детектор
трещин (band), авто-очистка выбросов (iqr) и пайплайн: CSV с сечениями → папка
образца в том же формате, что у референса Python и портов
C++/C/Go/JS/Java/Kotlin/Rust/Pascal/Swift/Julia/R/C#.

**Внешних пакетов нет** (`io`, `statistics`, `jsonencode/jsondecode` не
используются): JSON-парсер и писатель, CSV, медианы/перцентили, QR-МНК и
ISO-дата написаны своими силами, поэтому порт работает на голом Octave.
Проверено на **GNU Octave 11.3.0** (x86_64-w64-mingw32).

Модулей в Octave нет, поэтому модуль — это **префикс имени функции**: файл на
функцию в `src/` (`signal_*`, `linalg_*`, `cleaner_*`, `detector_*`, `model_*`,
`json_*`, `csv_*`, `document_*`, `conformance_*`, `selftest_*`), а каталог
подключается `addpath`. Имена функций обязаны совпадать с именами файлов —
это требование Octave, не стилистика.

Модель — **структура со ЗНАЧЕНИЕМ** (в R это было окружение, в Julia — mutable
struct): каждый «мутатор» возвращает её обратно, поэтому обучение выглядит как
`m = model_fit(m, angles, radii)`. Забыть присваивание — значит молча работать
со старой моделью.

## Запуск

```powershell
powershell -File octave/build_octave.ps1            # проверка загрузки порта
powershell -File octave/build_octave.ps1 -Test      # самопроверка (bin/selftest.m)
powershell -File octave/build_octave.ps1 -Vectors   # конформанс-векторы
powershell -File octave/build_octave.ps1 -Pipeline  # пайплайн на python/synthetic_data.csv

# вручную (скрипт печатает ровно эти команды; octave-cli.exe ищется в
# %LOCALAPPDATA%\Programs\GNU Octave\Octave-<версия>\mingw64\bin):
octave-cli --no-gui --quiet --no-init-file octave/bin/conformance.m spec/conformance/vectors
octave-cli --no-gui --quiet --no-init-file octave/bin/selftest.m    spec/conformance/vectors
octave-cli --no-gui --quiet --no-init-file octave/bin/pipeline.m `
    --input python/synthetic_data.csv --out-dir samples/synthetic_sphere_octave --name synthetic_sphere
python python/studies/verify_port.py --py-dir samples/synthetic_sphere `
                                     --cpp-dir samples/synthetic_sphere_octave
```

Ключи пайплайна: `--input`, `--out-dir` (обязательны), `--name`, `--description`,
`--no-pits`, `--quiet`. По умолчанию — как в референсе: N=7, фаза 24.75°, степени
4…14, авто-iqr, фичер ям включён. CSV читается по заголовку: нужны колонки
`section_id, height_mm, angle_deg, radius_mm` (остальные колонки файла
игнорируются, порядок не важен).

`--no-init-file` отключает пользовательский `~/.octaverc`: пакетов у порта нет,
так что настройки не нужны, а прогон становится воспроизводимым. `--no-gui`
нужен, чтобы не поднималось окно графики.

## Состав

| Файл | Назначение |
|---|---|
| `src/signal_*.m` | медиана/перцентили/MAD/окна по кольцу/фильтры — как numpy; `signal_round_even` — округление «половина к чётному» |
| `src/linalg_*.m` | МНК через QR (Хаусхолдер) + базис Чебышёва (Кленшоу) |
| `src/cleaner_*.m` | авто-очистка выбросов (iqr): медианный фильтр + усы Тьюки |
| `src/detector_*.m` | детектор ям: узкая/широкая медиана, индикатор в MAD-ах, зоны |
| `src/model_*.m` | модель: локальные степени, smoothstep-смешивание, фичер ям, метрики |
| `src/json_*.m` | мини-JSON: парсер + рендерер дерева + числовое форматирование + файловый ввод-вывод |
| `src/csv_*.m` | чтение CSV по заголовку + посекционный расчёт |
| `src/document_*.m` | документ `NN.pappa.json` и папка образца (`sample.json`) |
| `src/conformance_*.m` | проверка конформанс-векторов (допуски как у остальных портов) |
| `src/selftest_run.m` | самопроверка: векторы + дымовой фит + круговая проверка документа |
| `src/pappa_nv.m` | пары «имя, значение» для структур параметров (в Octave нет именованных аргументов) |
| `bin/conformance.m` | проверка порта по векторам (коды 0/1/2) |
| `bin/selftest.m` | самопроверка (коды 0/1) |
| `bin/pipeline.m` | пайплайн: CSV → папка образца |
| `build_octave.ps1` | поиск `octave-cli.exe` + прогоны (`-Test`/`-Vectors`/`-Pipeline`) |

## Заметки о совместимости (что реально всплыло при портировании)

* **`round` округляет половину ОТ НУЛЯ** (`round(2.5) == 3`) — как в
  C/C++/Pascal, в отличие от `Python round()`/R/`Math.RoundToEven`. Для ширин
  окон («половина к чётному») написан `signal_round_even`; при этом
  `printf('%.0f')` в Octave округляет половину К ЧЁТНОМУ (это проверено
  отдельным тестом) — на нём держится запись целых в JSON.
* **`rem` ≠ `mod`.** `mod` в Octave — floor-деление (как `%` в Python):
  `mod(-1, 360) == 359`, а `rem(-1, 360) == -1`. Все кольцевые формулы идут
  через `mod`, иначе расстояние по кольцу уезжает на 360.
* **Implicit expansion вместо ошибки формы.** `1×k .* k×1` в Octave — не
  ошибка, а матрица `k×k`. Именно так падал обратный ход МНК
  (`sum(a(i, k:n) .* x(k:n))` давал вектор); правильная запись — произведение
  `строка * столбец`.
* **Формула окна по кольцу — `mod(i − h − 1 + (0:w−1), n) + 1`.** Потерянная
  «−1» (в R-порте она есть) сдвигает фильтр на точку вправо, а вместе со
  сглаживанием — на две: детектор уезжал на 2° (это и поймал `vector_03` —
  зоны стояли на 88°/208° вместо 90°/210°), а очиститель находил 4 выброса
  вместо 9.
* **`struct('f', {})` — это пустой МАССИВ структур, а не структура с пустым
  полем** (0×0, и обращение к полю падает с «Invalid call to numel»). Пустой
  список в поле пишется двойными фигурными: `struct('f', {{}})`.
* **Структуры — значения.** Модель копируется при передаче в функцию, поэтому
  `m = model_fit(m, ...)`; счётчики самопроверки тоже возвращаются наружу
  (`[passed, failed] = check(...)`), а не мутируются на месте.
* **Писатель JSON — обход дерева, а не буфер.** Порядок ключей задаётся
  порядком полей структуры (Octave его сохраняет), а вставки «как есть» —
  `null` в поле `detector` и компактный объект `cleaner` — помечаются обёрткой
  `json_raw(...)`.
* **Состояние парсера — двухэлементный вектор** `[позиция, длина]`, а сам текст
  идёт отдельным аргументом: если сложить текст внутрь состояния, Octave
  копировал бы 40 КБ на каждом шаге по символу (векторы конформанса — 42 КБ).
* **Медианный фильтр векторизован матрицей индексов** (`n×w` + `median(X, 2)`):
  цикл по точкам стоил бы секунды на сечение (6000 точек × окно 167), поэтому
  пайплайн идёт ≈11.5 с, а не минуты.
* **CSV — `textscan` по числу колонок из заголовка + `str2double`.** Свой
  `strsplit` в Octave по умолчанию СКЛЕИВАЕТ пустые поля
  (`collapsedelimiters = true`), что ломает карту колонок; строки читаются одним
  куском, а нужные четыре колонки выбираются по имени.
* **UTC-отметка — через `time()`/`gmtime`**, а не `clock()`/`localtime()`:
  последние дают местное время, и в документах был бы сдвиг часового пояса.
* **Запись файлов — байтами** (`fwrite` + `uint8`), а не текстовым `fprintf`:
  проверено, что Octave не переводит `\n` в `\r\n`, но байтовая запись
  фиксирует это независимо от платформы (в документах нет `\r`, это отдельный тест).
* **Скрипты ≠ функции.** `bin/*.m` — скрипты: функцию нельзя определить в конце
  файла и вызвать в начале (она появится только при выполнении), поэтому
  подсказка по ключам печатается прямо в месте ошибки.
* **`mkdir` создаёт промежуточные каталоги** (как `dir.create(recursive = TRUE)`
  в R), а `dir()` + `sort()` дают тот же порядок векторов, что у других портов.
* **Кодировка консоли.** Исполняемый текст порта — ASCII (сообщения
  по-английски); кириллица осталась в комментариях и в одном месте данных —
  поле `description` документов (`сечение N, h=N мм`), как у портов C# и R: оно
  пишется байтами UTF-8, и JSON от этого не страдает. Причина та же, что у
  `.ps1`-файлов репозитория: консоль Windows в разных кодовых страницах иначе
  печатает мусор.
* **`--no-init-file`** в `build_octave.ps1`: пользовательский `~/.octaverc` не
  влияет на прогон (пакетов у порта нет), поэтому результаты воспроизводимы.
